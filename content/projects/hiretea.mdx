# Hiretea

Hiretea is a technical hiring platform that runs the whole process in one
workspace, from first application to final offer.

[Website](https://hiretea.dev)

## Overview

Technical hiring usually lives in five disconnected tools: an ATS, an
assessment platform, a code host, a video-call app, and a spreadsheet that
tracks what actually happened. Hiretea consolidates applications, structured
assessments, repository-based coding challenges, live interviews and final
decisions onto a single connected candidate record, and records every step on
an append-only audit trail. Candidates see the stages and the effort expected
of them up front; reviewers decide with evidence attached.

- **Structured assessments**: versioned questions with auto-scoring for
  multiple choice and human scoring for written and code answers.
- **Repository challenges**: candidates work in a private Git copy of a real
  repository and submit exact commits for review. No zips, no screenshots.
- **Live interviews**: built-in encrypted HD video, screen sharing and chat,
  so interview links never leave the platform.
- **Transparent decisions**: stages, rubrics and reviewer notes are visible to
  the people who need them, and every decision is recorded with evidence.

## Who Is It For?

- **Hiring teams** who want full control over their technical hiring pipeline
  without sending candidate data to third-party services.
- **Engineering managers & recruiters** who need structured case assignments,
  reviewer guides, rubrics, and decision tracking in one place.
- **Candidates** who receive a repository to work in, push code via standard
  `git`, and optionally open pull requests to submit their work for review.

## How It Works

1. **Bootstrap** — On first boot, the stack automatically sets up PostgreSQL,
   initializes Gitea with an admin account, registers an OAuth application,
   applies the database schema, and seeds the first workspace admin. A manual
   `/setup` page is available as a fallback.
2. **Create templates** — Admins define case templates that point to Git
   repositories. A template can provision a brand-new repo, link an existing
   one, or copy from an existing repository. Each template carries reviewer
   assignments, review guides, and rubric criteria with weighted scores.
3. **Provision candidates** — Recruiters provision candidate accounts, which
   automatically creates a Gitea user with an initial password and a linked
   identity record. Invite links (with token hashing, expiration, and
   revocation) are generated for onboarding.
4. **Assign cases** — Assigning a template to a candidate creates a working
   repository (mirrored from the template), grants the candidate write access,
   registers a webhook for status tracking, and persists the case row in
   `READY` status.
5. **Candidate works** — The candidate pushes code to their working
   repository. Webhook deliveries automatically advance the case status: first
   push → `IN_PROGRESS`, review-submission PR → `REVIEWING`.
6. **Interview & review** — Reviewers meet candidates in built-in live
   interviews, then use the review workflow with the template guide and
   rubric, leaving evaluation notes with scores and summaries.
7. **Decide & audit** — Cases are finalized with a decision (`ADVANCE`, `HOLD`,
   or `REJECT`). Every meaningful mutation (provisioning, status changes,
   access grants, invite lifecycle, webhook deliveries, AI runs) is recorded
   in an append-only audit log.

## AI, With Guardrails

Hiretea's AI proposes next steps, such as
advancing a candidate, but every proposal requires human approval. Fit review
and code review come back with attached evidence and confidence levels, and
every AI run is written to the audit trail. Model keys are bring-your-own, and
an MCP server lets tools like Claude Desktop or Cursor read candidate
snapshots and pipeline data directly.

## Deployment

Two deployment modes share the same codebase:

- **Self-host**: everything runs behind your own firewall. Gitea is bundled as
  the code host and stays internal-only; all Gitea traffic flows through a
  small Bun gateway with a control-plane token, and authentication uses Gitea
  OAuth with database sessions.
- **SaaS**: authentication uses provisioned Hiretea credentials, with JWT
  claims carrying role and workspace access. Gitea remains the git-hosting
  identity behind the gateway.

Object storage is S3-compatible in both modes: an in-stack SeaweedFS overlay
for local and bundled deployments, or any external provider such as Hetzner
Object Storage in production. Production runs multi-stage Docker images built
in GitHub Actions and orchestrated with Docker Compose; the deploy target
(Coolify) pulls immutable commit-SHA-tagged images from GHCR, so rollback is
just re-pointing to an older image. Self-hosted licensing is coming soon; see
[hiretea.dev](https://hiretea.dev) for details.

## Technology Stack

- **Language & runtime**: TypeScript everywhere; Bun as the runtime for the
  API, gateway, worker and tooling.
- **Application**: Next.js 16 with React 19, Radix Themes, Monaco editor,
  Framer Motion, dark-mode-first UI.
- **API**: a NestJS service on the Express platform, plus a dedicated worker
  process for background jobs.
- **Gateway**: a small Bun service (validated with Zod) that proxies and
  guards all Gitea traffic.
- **Data**: PostgreSQL with Prisma; S3-compatible object storage via the AWS
  SDK.
- **Git**: Gitea as the bundled code host, internal-only behind the gateway.
- **Real-time**: LiveKit for encrypted video interviews and screen sharing.
- **AI**: Model Context Protocol SDK for tool integrations, pluggable model
  providers, human-in-the-loop approval on every run.
- **Delivery**: layered Docker Compose stacks for self-host and SaaS, GitHub
  Actions CI, Vitest unit and integration tests, Playwright end-to-end tests,
  Lighthouse CI.
- **Admin console**: a separate Vite + React 19 application with React Query.
